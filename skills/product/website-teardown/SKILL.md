# Website Teardown

Perform a structured analysis of any website — competitor, inspiration, or the user's own — that makes the site's decisions legible. What's intentional, what's accidental, what's working, what's not. The deliverable is a teardown document, not a redesign.

This is an analytical skill. It produces understanding, not solutions. Use it before running competitive-positioning, before redesigning your own site, or when someone says "I like this site but I can't articulate why."

## Process

### 1. Fetch & observe

Load the site using WebFetch. Before analyzing anything, record the first impression — the 0-5 second reaction:

- What do you understand immediately? Can you state what the product does in one sentence?
- What's the visual hierarchy communicating? Where does the eye go first, second, third?
- What's the intended audience? Can you tell who this is for?
- What's the emotional register? Premium, playful, enterprise, technical, consumer?
- What's unclear or missing from the first screen?

Write this down before proceeding. First impressions cannot be reconstructed after deep analysis — they're gone the moment you start reading carefully.

### 2. Tear down by dimension

Analyze the site systematically using the eight dimensions in DIMENSIONS.md. Do not try to cover everything equally — focus on what's most notable. Every site has 2-3 dimensions where it's strong and 2-3 where it's weak. Find those.

For each dimension, note:
- What specific decisions were made (not "good typography" — which typeface, what scale, what hierarchy)
- Whether the decision appears intentional or default
- How it compares to the category norm (is this standard, differentiated, or behind?)

Cross-reference trust-building-patterns/TRUST-SIGNALS.md for the trust dimension. Cross-reference ai-design-polish/REFERENCE-PATTERNS.md for design quality benchmarks.

### 3. Synthesize

Produce the teardown document using the format in TEARDOWN-FORMAT.md. Lead with the verdict — the strongest move and the biggest miss. The reader should understand the site's essential character in the first three sentences.

Score each dimension (1-5) but don't let scores replace analysis. A score is a summary; the analysis is the substance.

### 4. Extract lessons

Adapt the output to the user's purpose:

- **Tearing down for inspiration:** Call out transferable patterns using the framework in PATTERN-EXTRACTION.md. Separate what's universal from what's context-dependent.
- **Tearing down for competitive intelligence:** Call out positioning gaps — what claims they make, what they avoid, where they're vulnerable. Reference COMPARATIVE-TEARDOWN.md if multiple sites are involved.
- **Tearing down their own site:** Focus on the gap between intent and execution — what the site is trying to communicate vs. what it actually communicates.

## Rules

- Always fetch the actual site. Don't analyze from memory or description.
- Record first impressions before deep analysis. They cannot be reconstructed.
- Be specific. "The typography is good" is not analysis. "They use Inter at a 3-step scale with tight heading line-height, which creates visual density that reads as technical/developer-focused" is.
- Be analytical, not mean. "This doesn't work because X" is useful. "This is bad" is not.
- Focus on what's most notable, not on comprehensive coverage. Every site has strong and weak dimensions — find them.
- Don't prescribe solutions unless asked. The teardown is for understanding. Solutions come after.
- For comparative teardowns of multiple sites, use COMPARATIVE-TEARDOWN.md for the structure.
